# Captain's Log — 2026-07-28
Heavy day split across two projects, both orbiting the same feature arc: a cinema experience that needed its data plumbing connected end-to-end.

Most of the foundational work happened in private-project-2, where I added the backend endpoints that the rest of the day depended on. Two separate additions: a general collections endpoint and a dedicated promo-collections endpoint that reads from Airtable. Keeping them separate made sense — the promo surface has different editorial ownership and different cache/freshness requirements than the standard collections, so conflating them would have been the wrong abstraction even if they look similar at the data layer.

With the API in place, the majority of the day shifted to wiring the frontend in private-project-1. The cinema feature branch got the collection page and collections rail pointing at the new `cinema_api` endpoints, and the homepage promo component now pulls its content from the Airtable-backed promo-collections endpoint. What had been hardcoded or stubbed is now live data. That's a satisfying milestone — the feature starts to feel real when it's breathing on its own.

Alongside that, I fixed cinema search state to sync with URL params, mirroring how the main search already works. It's one of those things that's easy to overlook during initial feature development but matters a lot for shareability and back-button behavior. Glad I caught it before it shipped.

The other chunk of today was less glamorous but genuinely important: a sweep of copy, accessibility labels, and French locale correctness. Twenty-two files touched fixing English user-facing text and a11y labels — tedious, but the kind of thing that compounds badly if left to accumulate. The French-specific fixes were trickier: search filter page reloads and hard navigations were misbehaving on French URLs, and "Voir tout" links weren't rendering French facet labels correctly. Both were localization edge cases where the routing logic wasn't accounting for locale prefixes the way it needed to.

Rounded out the day with a caching improvement: HTML responses now served with `no-cache` while hashed static assets get `immutable`. Classic pattern, but it's one of those things that quietly causes cache-poisoning headaches until you actually set it up right.
