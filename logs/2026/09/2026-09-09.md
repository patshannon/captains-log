# Captain's Log — 2026-09-09
Heavy day. Forty commits across a single private project, and the bulk of them land the **forge flow** — a fundamental re-architecting of how shows go from intake to publish.

The forge flow replaces the old Prepare-to-Publish pipeline with something much more opinionated. The core idea: Forge owns creation end-to-end. The writer's show page becomes a preview; the real workspace lives under `/forge/shows/[showId]`. The Prepare rail is the spine — segments → art → theme → main paths, with Publish held until everything renders AND the main path is walked. I made the walk optional in D26, which was a late but necessary concession: an unwalked main path shouldn't block Publish for shows that are purely bank-driven. The Scenes stage sits between, pending until walked, current only while the BOT is live.

The review got some love too. It's now editable at $0 — a pencil on every field the forge produced, before Accept. The review also shows how long and how much, and I collapsed three separate note lists into one. Cleaner UX, less cognitive load for the writer.

On the play side, I fixed a stubborn bug with endorsed paths. ONE endorsed path per fork — starring a path clears the stars at that fork. The step-back now lists the path the player actually wrote, and endorsed free text leads the sheet. Also turned lookahead off for every run. Every run create now pins `config.lookahead: off`. That's been a long time coming.

The fixture-API mode is worth noting. `NEXT_PUBLIC_API_FIXTURES=1` with `pnpm dev:fixtures` means the writer surface can answer from test fixtures on a fast clock. That'll unblock frontend work without waiting for backend deploys.

Forty commits is a lot for one day. The forge flow PR alone touched 132 files across the merge. I'm calling this one done and letting the changes bake overnight.
