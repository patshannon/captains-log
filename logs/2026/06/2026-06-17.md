# Captain's Log — 2026-06-17
Spent most of today tackling a configuration migration that's been on the backlog for a while — moving a Firebase project off the deprecated `functions.config()` API and onto a proper secrets management setup using dotenv locally and Secret Manager in production. Thirty-seven files touched, which tells the whole story about how deeply the old config pattern had been threaded through the codebase.

The `functions.config()` approach was always a bit of a crutch — Firebase's own proprietary key-value store that worked fine until it didn't, and Google has been signaling for a while that it's on the way out. The right split here is dotenv for local development (fast iteration, no network calls, familiar to every developer who's touched a Node project in the last decade) and Secret Manager for deployed environments where you actually need audit trails, IAM-scoped access, and rotation support. It's a more mature posture and the operational story is cleaner.

The tedious part is always the mechanical work of tracking down every `functions.config().someService.someKey` reference and replacing it with `process.env.SOME_KEY` — and then making sure the Secret Manager bindings actually exist with the right names before you push to any real environment. Thirty-seven files means this wasn't a localized concern; it had spread into callable functions, background triggers, HTTP handlers, the works. Good to have it done cleanly rather than in a piecemeal way.

No PRs opened yet — I want to do one more pass and make sure the local `.env` documentation is solid before I put this up for review. The kind of migration that looks straightforward in a diff but can quietly break a staging environment if someone doesn't know what environment variables to provision.
