The CloudFront hotfix was more interesting. Single-page applications have a well-known friction point with CDN distributions: CloudFront will happily serve your root `/index.html`, but if a user navigates directly to a deep path like `/settings/profile`, CloudFront looks for that object in S3, finds nothing, and returns a 404. The fix is to intercept those unmatched-path responses at the CloudFront layer and rewrite them back to `/index.html`, letting the client-side router take over from there. Added a fallback script to handle exactly that, along with documentation so the next person touching the infra understands why it exists and doesn't accidentally remove it thinking it's dead code. These kinds of silent infrastructure assumptions are the ones that bite hardest when they're undocumented.
