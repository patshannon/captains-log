# Captain's Log — 2026-06-29
Day 180, and private-project-1 had an absolute avalanche of activity — 18 commits, a fistful of merges, and two new PRs opened that set up the next wave. This was a productive shipping day.

The biggest structural change was swapping the public `/api/diagnose` REST route for a Next.js Server Action. The motivation is sound: there's no reason to expose that surface as a public HTTP endpoint when it's only ever called from the authenticated UI. Server Actions give you colocation, implicit auth context, and fewer moving parts. The tradeoff is that you lose the ability to call it externally, but for a feature behind a login that's purely a benefit.

Alongside that, the diagnosis flow got meaningful product guardrails for the beta. A per-user daily quota is now enforced at three scans, with the remaining count surfaced in the UI. The quota gate went through a few iterations — the initial implementation landed, then got hardened separately, which suggests the first pass had a race condition or wasn't checking the right identity boundary. That kind of iterative tightening on rate-limiting logic is normal; the first version almost always has a subtle hole. There's also a client-side image resize step before upload, which is the right call for bandwidth and cost — no reason to push a 4MB HEIC to the server when a compressed JPEG at reasonable resolution is sufficient.

On the engagement and retention side, two features shipped: a post-diagnosis feedback prompt and a mechanism to surface feature-request prompts to engaged users. The feedback capture is straightforward — get signal on diagnosis quality while intent is high. The feature-request prompt is a bit more speculative, but if you're building with a small beta cohort, actively soliciting feature votes early shapes the roadmap in useful ways. There was a bug in that flow where a note-blur event was incorrectly re-asserting an un-vote, which is exactly the kind of subtle event-handling edge case that's easy to miss when wiring up optimistic UI.

Two new PRs are open heading into tomorrow: a lawn profile (postal code, area, grass type) and a "Coming to Pro" teaser with feature voting. The profile work also included a quick fix capping the area column to `numeric(10,2)` to avoid an upsert overflow — easy to overlook until it bites you in staging.

Solid day. The foundation is coming together.
